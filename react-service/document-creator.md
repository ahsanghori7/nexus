# Document Creator (src/v1/document-creator)

This page documents how the document-creator feature is pieced together so future frontend work can move quickly.

- **Primary entry point:** `src/v1/document-creator/components/template/index.jsx` (`DocumentCreator` class + `WrapperDocumentCreator` for routing).
- **Supporting services/helpers:** `services/template/forms` (form builder/handler), `services/document-builder` (renders the doc JSON), `helpers/config.js` (JSON ↔ HTML shortcode transforms & template mutations).

## Main Components
- `DocumentCreator` (`components/template/index.jsx`): Orchestrates fetch/save, holds state (`config`, `draft`, `formConfig`, `formValues`, `meta`, etc.), wires header actions, triggers document refreshes, and feeds the PDF preview + form panes.
- `Page` + `Header` (`components/page/*`): Shell wrapper; header renders progress, preview/save/send, approval/witness modals, and Docusign toggles. Progress is driven by `TemplateService.getFormPercentage`.
- `FormConfig` (`components/template/form-config`): Renders form fields generated by `TemplateService` and handles observer-driven updates. Receives refs for focus/scroll highlighting.
- `ClinkPDF` (`components/template/pdf/index.jsx`): Right-hand preview. Wraps MUI `Backdrop` for loading and renders `DocumentBuilderComponent`.
- `DocumentBuilderComponent` (`components/template/pdf/DocumentBuilder.jsx`): Thin wrapper that instantiates `services/document-builder/DocumentBuilder` and calls `build(...)` with config + shortcodes + handlers.
- `ContentEditor` (`components/template/pdf/content-editor`): When a config node is editable text, opens a modal rich-text editor. Uses `Config.cleanHtml`/`getJSONfromHTML` to normalize the edited value before saving back.

## How Data Is Handled
- **Initial load (`initPage`)**
  1) If `showForm` is true (template editor flow), fetch project/tender info for file manager folders.
  2) Fetch document content (`Relay(action, 'getContent')`) → sets `config` + `draft` (deep copy) + `meta`/`soa`/`soamc`/`miniBoq`/`simpleRowQuotePrice` flags.
  3) Fetch form config (`Relay('template','config')`) and store slug; hand to `TemplateService.buildForm`.
  4) Inject header/footer/company info, SOA/SOA_MC rows, Mini BOQ rows, Simple Row Quote, and file-manager document rows into the JSON via `Config.setHeaderFooter`, `setScheduleOfAttendances`, `setMiniBoq`, `setSimpleRowQuotePrice`, `setDocumentsInConfig`.
  5) For select/reference fields that require remote data, `TemplateService.updateTemplateServiceSecond` issues `Relay` calls defined in form config `source` to populate options and initial values.
  6) After all async hydration, preview + form render with refs for scroll syncing.
- **State kept in `DocumentCreator`:** `config` (live JSON), `draft` (last-saved snapshot), `formValues`, `formErrors`, `meta` (quote/order info, signatory, vat, miniboq flags, etc.), and UI flags (loading, open modals, focused inputs).
- **Saving content:** `handleConfigSave` strips per-page header/footer nodes, then POSTs the sanitized config to `document` or `template` `saveContent` endpoints. On success it copies `config` → `draft`.
- **Saving form values:** `TemplateService.saveData` PATCHes on every blur/callback. Values are mapped from UI names back to backend keys via `TemplateService.mapping` and normalized with `formatValues` (dates, selects → ids, money normalization, text extraction). Derived observer fields run through `applyObserverActions`.
- **Mini BOQ / SOA updates:** Custom components inside the doc JSON call `handleUpdateAttendance` or `handleLocalMiniBoq`; both persist via `Relay('template','saveContent')`, then re-run `loadScheduleAttendances`/`loadMiniBoq` to refresh injected rows.

## Building the Document From JSON → React/HTML
- **Config shape:** A nested array of nodes coming from the backend (e.g., the root document has `children` pages; pages have `view`/`text`/`image`/table rows, etc.). Nodes can include custom `name` for specialized renderers (attendance-checkbox, miniboq-input, money-input, percentage-input, add/delete attendance buttons) and arbitrary `props/style`.
- **`DocumentBuilder.build` (`services/document-builder/index.jsx`):**
  - Recursively walks the config tree. Generates a `uniqueKey` that encodes depth (`levelId-item.index`).
  - Chooses the React component: base `Div` for generic nodes, `Img` for `image`, or special controls for attendance/BOQ/money/percentage depending on `elem.name`.
  - For leaf text nodes, runs `getShortcodeContent` to replace any `{data_shortcode}` with the provided `shortcodes` map and flags if the currently-focused input appears in the string so the preview can highlight it.
  - Calls `getContent` to convert inline HTML-style tokens (see below) into an array of strings/React elements handed to `ContentEditor`.
  - Passes `handleConfigChange` (if provided) into `ContentEditor`, which lets users edit content and push changes back via `DocumentCreator.handleConfigChange`.
  - Propagates handlers for attendance/BOQ/vat controls and respects `editable` flags.
- **`getContent` (`services/document-builder/getContent.js`):** Splits a string containing `{...}` tokens into an array. Handles:
  - Plain text (no `{}`) → string array.
  - Inline HTML shortcodes like `{b:Bold}`, `{ul:{li:Item}}`, `{br}` by invoking `htmlParser[tag]` for each segment.
  - Nested or adjacent tokens by recursively slicing on braces while keeping ordering intact. Uses `MAX_HTML_TAG_OPT_SIZE` = 6 to locate tag names quickly.
- **`htmlParser` mapping (`services/document-builder/htmlParser.jsx`):** Converts shortcode tags to React nodes (`br`, `hr`, `b`, `bred`, `bpnk`, `binv`, `inv`, `em`, `u`, `mark`, `ul`/`ol`/`li` + indented variants, `gp` for non-breaking spaces, `hrt` separator). Keys include UUIDs to keep React happy.

## Shortcodes
- **Data shortcodes (form-driven placeholders):**
  - `DocumentCreator.formatFormValues` flattens `formValues` into plain strings (dates formatted, select labels pulled, editors → text, money → currency) then `replaceShortcodes` resolves nested `{foo}` inside other values.
  - These resolved values are passed to `ClinkPDF` → `DocumentBuilder.build` as `shortcodes`.
  - `getShortcodeContent` scans each content string for `{shortcode}` tokens and replaces them. If the token corresponds to the currently-focused form input, the preview applies `focused` styling to the surrounding element.
  - Some nodes can hide/show content based on form values (e.g., `elem.conditionalContent` on a `page` toggles `hide-number-document` when the referenced form field is truthy).
- **HTML shortcodes (inline formatting tokens inside content):**
  - Stored in the JSON as `{b:Text}`, `{u:Underline}`, `{br}`, `{lind:Indented list item}`, etc.
  - `getContent` + `htmlParser` convert them into real React elements for display.
  - When an editor is open, `Config.getJSONfromHTML` reverses the process: it strips HTML tags and replaces them with shortcode tokens so the backend continues to store compact, serializable strings. `Config.cleanHtml` normalizes cursor spans/entities before conversion.
  - Special cases for repeated `{br}`/`{gp}` are handled to prevent recursion errors.
